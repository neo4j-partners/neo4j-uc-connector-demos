= Validation
:description: Databricks bundle-based validation jobs for the Neo4j Unity Catalog federation notebooks and advanced patterns

The `validation/` directory contains Python scripts that run on Databricks as multi-task jobs defined in a Databricks Asset Bundle. They are the automated execution path for the getting-started notebooks and selected advanced patterns.

Use `validate.py` as the only validation entry point:

[source,bash]
----
cd validation
uv run python validate.py --help
----

The script is a thin wrapper around `databricks bundle deploy` and `databricks bundle run`. The Databricks Asset Bundle is defined in the repo-root `databricks.yml` and `resources/*.yml` (the `notebook_parity`, `extras`, and `metadata` jobs). Runtime configuration is read from the repo-root `.env`, converted into `--var name=value` flags, and passed to the bundle commands. Neo4j credentials are stored in a Databricks secret scope by `./create_secrets.sh` at the repo root.

== Default Notebook-Parity Run

[source,bash]
----
cd validation
uv run python validate.py run
----

`validate.py run` deploys the bundle and runs the `notebook_parity` job, which executes notebook-parity scripts in notebook order as a multi-task DAG.

[cols="1,3"]
|===
|Script |Purpose

|`run_00_load_graph.py`
|Loads the aircraft graph into Neo4j from CSV files in a UC Volume

|`run_01_connection_setup.py`
|Creates `sensor_readings`, lakehouse helper tables, and the UC JDBC connection

|`run_02_federated_queries.py`
|Runs the live federated query sections from the getting-started tutorial

|`run_03_materialized_tables.py`
|Materializes `neo4j_*` Delta tables and validates SQL/federated queries

|`run_05_metadata_sync_external_api.py`
|Registers Neo4j schema through the External Metadata API

|`run_06_new_federated_queries.py`
|Validates advanced `remote_query()` SQL and Delta joins
|===

`advanced-patterns/07_performance_diagnostics.ipynb` remains a manual notebook for latency and throughput investigation. It has no automated validation script.

== Extra Regression Coverage

Broader smoke checks live in a separate `extras` job:

[source,bash]
----
uv run python validate.py extras
----

[cols="1,3"]
|===
|Script |Purpose

|`run_extra_connection_smoke.py`
|Runs broader connection checks across the Python driver, Spark Connector, direct JDBC, UC JDBC, and `remote_query()`

|`run_extra_federated_regression.py`
|Runs federated query regression checks beyond the getting-started notebook coverage

|`run_extra_metadata_sync_tables.py`
|Discovers and materializes all Neo4j labels and relationships as Delta tables
|===

== First-Time Setup

From the repo root:

[source,bash]
----
cp .env.sample .env
./getting-started/upload_data.sh
./create_secrets.sh
----

Then run validation setup from `validation/`:

[source,bash]
----
uv sync --locked
uv run python validate.py check
uv run --with neo4j python tools/check_neo4j_auth.py
uv run python validate.py run
----

For repeat runs where the bundle is already deployed:

[source,bash]
----
uv run python validate.py run --skip-deploy
----

To target a non-default bundle target:

[source,bash]
----
uv run python validate.py run --target prod
----

== Metadata Validation

The metadata suite has two paths:

* `run_extra_metadata_sync_tables.py` materializes discovered Neo4j labels and relationship types as Delta tables.
* `run_05_metadata_sync_external_api.py` registers discovered Neo4j schema as Unity Catalog External Metadata entries.

The External Metadata API path requires `CREATE_EXTERNAL_METADATA` on the metastore. The `metadata` DAB job handles this automatically: its first task issues the grant, then both metadata paths run.

[source,bash]
----
uv run python validate.py metadata
----

For repeat runs where the bundle is already deployed:

[source,bash]
----
uv run python validate.py metadata --skip-deploy
----

See xref:metadata-synchronization.adoc[Metadata Synchronization] for the design and privilege details.
