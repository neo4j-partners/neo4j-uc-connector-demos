= Neo4j + Databricks Lakehouse Federation
:description: Query Neo4j graph data from Databricks through Unity Catalog JDBC, federated SQL, metadata synchronization, and Genie

[.lead]
This project shows how to use the https://github.com/neo4j-labs/neo4j-unity-catalog-connector[Neo4j Unity Catalog Connector] to query Neo4j graph data with SQL from Databricks. You write SQL against Neo4j as if it were a relational source. The Neo4j JDBC driver translates that SQL into Cypher, runs it against the graph, and returns the results as tables.

The connection works through Unity Catalog's JDBC support, so Neo4j access is governed by the same permissions, credentials, and audit controls as the rest of your lakehouse. Once connected, you can join Neo4j graph data with Delta tables in a single query.

This repo also demonstrates how to make Neo4j schema visible in Databricks Catalog Explorer through metadata synchronization, and how to make Neo4j data queryable in plain English through Databricks AI/BI Genie. All queries shown in this repo ran on a live Databricks cluster running Runtime 17.3 LTS connected to Neo4j Aura. The output is real, not mocked.

Start with the root README and the `getting-started/` notebooks. The site explains the same flow in browsable form.

[cols="1,2"]
|===
|Requirement |Purpose

|Custom JDBC on UC Compute
|Loads the custom Neo4j JDBC connector JAR in a Unity Catalog connection

|`remote_query` table-valued function
|Runs SQL against the UC connection from Databricks SQL

|Neo4j Aura instance
|Stores the aircraft digital twin graph

|Neo4j JDBC Lakehouse Federation Connector JAR
|Bundles the Neo4j JDBC driver, SQL-to-Cypher translator, and Spark subquery cleaner

|SafeSpark memory settings
|Prevents the Databricks JDBC sandbox from running out of metaspace while loading the driver

The required SafeSpark settings are documented in xref:uc-integration-setup.adoc[UC Integration Setup] and xref:troubleshooting.adoc[Troubleshooting].

=== Configure, Upload Data, and Create Secrets

[source,bash]
----
cp .env.sample .env
./getting-started/upload_data.sh
./create_secrets.sh
----

Set `UC_CATALOG`, `UC_SCHEMA`, `UC_VOLUME`, `DATABRICKS_PROFILE`, the Neo4j credentials, and the connector JAR path in `.env` before running the scripts. The upload script copies the aircraft digital twin CSV files into a UC Volume. The secrets script stores `NEO4J_USERNAME` and `NEO4J_PASSWORD` in the Databricks secret scope named by `DATABRICKS_SECRET_SCOPE`.

== Integration Patterns

=== JDBC Connectivity

Neo4j connects to Unity Catalog through a generic JDBC connection of `TYPE JDBC`, using the Neo4j JDBC driver with SQL-to-Cypher translation enabled. Databricks sends SQL, the driver translates it to Cypher, and Neo4j returns tabular results.

The connection supports aggregate queries, row-level SELECT, GROUP BY, HAVING, ORDER BY, JOINs, schema discovery, and Spark DataFrame reads when the required SafeSpark settings and `customSchema` options are applied. See xref:sql-reference.adoc[SQL Reference] for the validated query patterns.

=== Federated Queries

Once connected, Neo4j graph data such as flights, airports, maintenance events, and component hierarchies can be joined with Delta lakehouse tables such as sensor readings and time-series analytics in a single Spark SQL statement. The source systems stay where they are, and Spark combines results at read time.

=== Metadata Synchronization

The JDBC connection registers credentials and a driver, but it does not expose Neo4j's schema as browsable UC objects. This project demonstrates two approaches to metadata synchronization:

* Materialized Delta tables, which copy Neo4j labels and relationships into managed tables with Catalog Explorer, `INFORMATION_SCHEMA`, and SQL access.
* External Metadata API registration, which records schema-level metadata for discoverability and lineage without copying Neo4j data.

See xref:metadata-synchronization.adoc[Metadata Synchronization] and xref:materialization.adoc[Delta Materialization].

=== Natural Language with Genie

Neo4j data materialized as managed Delta tables becomes queryable through Databricks AI/BI Genie. Users ask plain-English questions, and Genie generates SQL across the materialized graph tables and Delta sensor tables. The LLM never sees Cypher and the user does not need to write SQL.

See xref:06-genie-natural-language.adoc[Natural Language Queries with Genie].

== What First-Class Federation Would Unlock

The integration works today through Unity Catalog's custom JDBC connection. Elevating Neo4j to an officially supported Lakehouse Federation source as `TYPE NEO4J` would replace current workarounds with native platform capabilities:

* Foreign catalogs that expose Neo4j schema as a browsable three-level Unity Catalog namespace.
* Table-level governance, data tagging, column lineage, and per-table audit logs.
* Broader Databricks-managed query pushdown, with potential graph-aware join pushdown.
* Genie and AI/BI dashboards querying Neo4j-backed foreign tables directly, without materialization as a prerequisite.
* Native service principal and OAuth-oriented credential management.

See xref:08-official-federation-catalog-governance.adoc[Catalog & Governance] and xref:09-official-federation-genie-analytics.adoc[Genie & AI/BI] for runnable Lakebase-based examples of the capabilities Neo4j would gain as an official federated source.
